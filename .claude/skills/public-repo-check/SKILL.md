# 公開前チェック

公開されるファイルとコミット履歴を確認し、結果を報告する。

## 守ること

- 読み取りだけを行う。ファイルの修正・削除、`git add`、`git commit`、`git push`、Gitの設定変更はしない
- 見つかった秘密情報は、報告に全文を書かない。ファイル名・行番号と、値の先頭数文字だけを示す
- ファイルの内容を外部サービスに送らない
- 実際の個人情報や秘密情報をこのスキルに書き足さない。このファイル自体も公開される

## 確認対象

公開されるファイルは次のコマンドで一覧にする。`.gitignore` で除外されたファイルは対象外とする。

```bash
git ls-files --cached --others --exclude-standard
```

`package-lock.json` などのロックファイルは、秘密情報の文字列検索だけを行う。

## 確認項目

1. **Gitの設定**：コミットの作成者メールアドレスが公開してよいものか確認する。`git config user.name`、`git config user.email` と、次のコマンドで過去のコミットの作成者も見る。コミットがまだなければ、その旨を報告する
   ```bash
   git log --all --format='%an <%ae> / %cn <%ce>' | sort -u
   ```
2. **対象ファイル**：`.env`、鍵、証明書、DB、ログ、バックアップ、作業メモ、ローカル設定（`*.local.*` など）が含まれていないか確認する。`.gitignore` の漏れがあれば指摘する
3. **秘密情報**：APIキー、トークン、パスワード、秘密鍵、認証情報付きのURLを探す。環境変数名や説明文だけの場合は問題なしと判断してよい
4. **個人情報**：メールアドレス、住所、電話番号、PCのユーザー名が入った絶対パスを探す
5. **画像と動画**：対象の画像と動画を一覧にする。`exiftool` が使えれば、位置情報と撮影機器の情報を確認する。使えないファイルは「未確認」として報告する。画像は読めるものを開いて、画面に写った地名、住所、個人名も確認する
6. **コミット履歴**：3と4を過去のコミットについても確認する。今のファイルから消えていても、履歴に残っていれば公開されることを指摘する
   ```bash
   git log --all -p
   ```
7. **公開してよい内容か**：README、CLAUDE.md、コメント、TODOを読み、自宅周辺や地域猫の居場所が分かる記述、社外秘の情報、公開を想定していないメモがないか確認する

## 報告の形式

次の4つに分けて報告する。該当がない区分は「なし」と書く。

- **要対応**：公開前に対処すべきもの。場所、理由、対処方法を書く
- **要確認**：公開してよいかを人間が判断するもの
- **未確認**：ツールがない、読めないなどの理由で確認できなかったもの
- **確認した範囲**：確認したファイル数、コミット数、検索した内容

最後に、「問題なし」と断定せず、「確認した範囲では見つからなかった」と伝える。検索で見つからない情報もあるので、人間が `git status` と差分を見て最終確認するよう促す。
